## [Unreleased]

### Добавлено

- **Меню «🧩 Битрикс ▾» для серверов с BitrixVM** — появляется в тулбаре после
  подключения, если на сервере найдены `/opt/webdir` и `/home/bitrix`:
  состояние сертификатов dehydrated (остаток дней, последние строки
  `dehydrated_update.log`) и перевыпуск `dehydrated -c`; отчёт по MySQL под
  Битрикс (hit ratio buffer pool, «дефолтные 128M») и тюнинг-файл
  `/etc/my.cnf.d/bitrix-tuning.cnf` с расчётом `innodb_buffer_pool_size` от RAM
  (40%, округление до chunk 128M); проверка доступа к базе по `dbconn.php`
  (пароль не попадает ни в командную строку, ни в отчёт — только через
  временный файл 0600); параметры и модули PHP; задание `cron.sh` (агенты);
  состояние postfix и глубина очереди `mailq`.
- **«Топ-таблицы базы (размер)»** в том же меню: `TOP-20` по `DATA_LENGTH +
  INDEX_LENGTH` из `information_schema` (база берётся из реквизитов `dbconn.php`,
  пароль — по-прежнему временным файлом 0600) плюс подсказки по таблицам,
  которые в Битриксе разрастаются именно мусором (`b_user_session`,
  `b_cache_tag`, `b_stat_hit`, `b_log`, `b_sale_basket`). Чистку делает штатными
  механизмами админки: ручное `DELETE` из `b_cache_tag` ломает инкрементальный
  кеш, поэтому кнопкой удаление не вынесено — только отчёт и рекомендации.
- **«Права файлов сайта» в том же меню** — типичное «распаковали архив под root,
  сайт упал»: проверка владельцев всего `/home/bitrix/www` (должен быть
  `bitrix:bitrix`), счётчик world-writable файлов (`-perm -o+w`) и запись в
  каталогах, без которых Битрикс не работает (`bitrix/cache`,
  `bitrix/managed_cache`, `bitrix/data`, `upload`, `bitrix/php_interface`).
  «Права файлов: починить» (с подтверждением) возвращает `bitrix:bitrix`,
  ставит 755 каталогам и 644 файлам и добавляет `upload` запись группой;
  действие прерывается, если группы `bitrix` в системе нет.
- **«Кеш: Redis / Memcached» в том же меню** — бэкенд кеша в `.settings.php`
  ищется как строковый литерал (слово в комментарии не считается), для
  redis/memcached проверяются systemd-юниты (в CentOS — `redis`, в Debian —
  `redis-server`) и `redis-cli ping`, плюс размеры `bitrix/cache`,
  `bitrix/managed_cache`, `bitrix/merged_cache`; «бэкенда нет — всё пишется в
  файлы» отдельно подсвечивается как главная причина тормозов на нагруженном
  сайте.
- **«Cron-агенты: установить в crontab»** — дописывает в crontab root ровно ту
  строку, которую рекомендует отчёт (общий литерал `CRON_LINE`): с бэкапом
  crontab через `common.save_crontab_backup`, без дублей (задание ищется по
  полному пути `cron.sh`) и с обязательной проверкой после записи — `rc=0`, но
  строки в crontab нет, считается ошибкой.
- **«Права на базу (SHOW GRANTS)» и «Права на базу: выдать недостающие»** в том
  же меню. Привилегии читаются под учёткой из `dbconn.php` через
  `CURRENT_USER()`, а не по `DBHost`: в `mysql.user` записан хост-паттерн
  (`%`, `%.site.ru`), и `GRANT` на другую строку учётки создал бы вторую учётку,
  ничего не починив. Отчёт сверяет набор с минимумом ядра Битрикса
  (`GRANT_REQUIRED`: DML + DDL + `EXECUTE`/`TRIGGER`/`EVENT`), различает
  `ALL PRIVILEGES` на `*.*` и на базу, выбрасывает `USAGE` (вход есть — делать
  нечего) и отдельно подсвечивает «права остались на другой базе»
  (переименовали/перенесли сайт) и правки по отдельным таблицам. Выдача — с
  подтверждением, одним `GRANT` недостающего на `{DBName}.*` под root-доступом
  (`/root/.my.cnf`), только после `ident_safe()` (имена вне
  `[A-Za-z0-9_$%.-]` в SQL не подставляются) и с обязательным перечитыванием:
  прав после выдачи меньше стало — сообщение честное, а не «готово».

### Изменено

- **Действия ISPmanager собраны в раскрывающееся меню.** Восемь кнопок в двух
  рядах заменены одним `🛠 ISPmanager ▾`: панель помещается в одну строку и не
  переполняется на узком экране. Состав и обработчики прежние; разрушительные
  действия (`Kill core`, `Отключить панель`) отделены разделителем. Диалоги
  подтверждения сохранены.
- Меню показывается только при определённой панели и блокируется при
  отключении — состоянием одного элемента вместо восьми кнопок.
- **Добавлено меню действий FastPanel** (`🛠 FastPanel ▾`): состояние панели и
  её стека (nginx/php-fpm/mysql, веб-интерфейс `:8888`, `nginx -t`), последние
  строки логов панели (`/var/log/fastpanel2`, `/var/log/fastpanel`),
  перезапуск службы панели и перезапуск веб-стека с обязательным `nginx -t`
  перед ним. Поддерживаются оба поколения: юниты `fastpanel2-engine` и
  `fastpanel`, версии php-fpm вида `php8.2-fpm`.

### Исправлено

- AST-страховка `tests/test_gui_smoke.py` не считала объявлением распаковку
  `self.a, self.b = ...` и считала такой атрибут «потерянным». Разбор целей
  присваивания вынесен в `add_self_targets` и покрывает кортежи, списки и
  `*`-элементы.

## [1.0.1] — 2026-10-09

### Исправлено

- **Бинарник не запускался на машинах без системного Tcl**: на старте окно падало
  с `::msgcat::mcmset: invalid command name` (трейс через `ttkbootstrap`).
  `package require msgcat` не находил модуль: PyInstaller раскладывает Tcl-модули
  (`.tm`) плоско в `_tcl_data/tcl8/`, а механизм `tm` ищет их в `tcl8/<версия>/`
  рядом с каталогом `_internal`. Спека теперь кладёт `msgcat`, `http`, `platform`
  и `tcltest` и туда тоже. На машине с установленным `tcl-tk` баг был не виден —
  там msgcat подхватывался из системы, поэтому релиз 1.0.0 «на developer-машине
  работал».

### Проверено

- Воспроизведение: бандл 1.0.0 с закрытым (`tmpfs`) `/usr/share/tcltk` падает 1-в-1
  с трейсом пользователя; бандл 1.0.1 в тех же условиях держит окно.
- `tests/test_spec_tcl.py` — 3 проверки раскладки `.tm` в спеке (всего 148 тестов).
  Тест исполняет преамбулу спеки, поэтому работает и без PyInstaller (в CI он не
  ставится): при отсутствии пакета подставляется стаб `collect_all`, а без Tcl-
  модулей в окружении проверки скипаются вместо падения прогона.

## [1.0.0] — 2026-10-09

Первый публичный релиз: инструмент закрывает полный цикл работы техподдержки —
подключение к серверу, диагностика, внесение правок, проверка результата.

### Добавлено

- **Подключение по SSH**: по паролю или приватному ключу, переключение между серверами
  без перезапуска, автоопределение панели управления (FastPanel / ISPmanager / без панели).
- **Профили серверов** (JSON с правами 0600) и история подключений.
- **Полная диагностика** одним отчётом: диски и inodes, память, CPU/load, службы,
  веб-конфиг, статусы служб — с прогрессом по этапам и возможностью отменить задачу.
- **Дополнительные проверки**: SSL-сертификат (срок действия), WHOIS домена,
  доступность портов, grep по логам, анализ доступа и OOM.
- **DNS**: проверка A / NS / PTR и смена резолверов с автоматическим учётом systemd-resolved.
- **Администрирование**: замена IP в конфигурационных файлах, перезапуск служб,
  редактор конфигов, бэкапы правок в `/root/tech_support`.
- **Управление ISPmanager** из окна программы.
- **Swap**: создание и удаление файла подкачки, правка `fstab`.
- **Файловый менеджер по SFTP**: навигация по каталогам, правка текстовых файлов,
  скачать/загрузить.
- **Интерактивный терминал**: история команд по стрелкам, поиск в выводе по Ctrl+F,
  копирование и сохранение отчёта, шпаргалка команд.
- **Темы интерфейса** на ttkbootstrap с автоопределением тёмной/светлой темы системы.
- **Маскирование секретов** в окне вывода и в сохраняемых отчётах.
- **Оформление репозитория**: LICENSE (MIT), `CONTRIBUTING.md`, `SECURITY.md`,
  шаблоны issues и pull request в `.github/`.
- **CI**: прогон `pytest` под Xvfb на каждый push/PR; Dependabot для pip и actions.
- **Сборка standalone-бинарника** через PyInstaller (команда и обязательные флаги —
  в README, готовый файл — в Releases).
- **Тесты**: 145 тестов, включая статический AST-слой, который ловит потерю метода
  или атрибута при переносе кода между `gui*.py`.

### Изменено

- `gui.py` разбит на mixin-модули: 1942 строки → 565 (`gui_themes`, `gui_profiles`,
  `gui_output`, `gui_runner`, `gui_checks`, `gui_swap`, `gui_dns`, `gui_admin`,
  `gui_isp`, `gui_files`). `DiagnosticApp` собираётся наследованием, публичный API
  (`get_theme_colors`, `DARK_THEMES`, `LIGHT_THEMES`) реэкспортируется из `gui.py`.
- `diagnostic.py` разбит на `common` / `metrics` / `logs` / `dns` / `files` / `panels` /
  `reports`; фасад сохранён для обратной совместимости импортов.
- Все удалённые команды переведены на `checker.run()` с проверкой кода возврата.
- Кнопки интерфейса разбиты на несколько рядов — в один ряд они не помещались.

### Исправлено

- Занятость не «залипает» после закрытия окна во время фоновой задачи: флаг сбрасывается
  первым, все колбэки идут через безопасный пост в UI-поток.
- `del active_checker` в `finally` убивал фоновый поток после каждой задачи
  (`UnboundLocalError` на последующих командах).
- `cancel_event` сбрасывается перед каждой задачей — после одной отмены переставали
  запускаться все остальные команды.
- Статусы служб больше не «съезжают»: формат `имя=статус` вместо позиционного списка.
- Бэкап конфигов при замене IPv6 и корректные проверки кода возврата диагностики.
- Команда сборки исполняемого файла: без `PIL._tkinter_finder` окно падало на старте
  с `invalid command name "PyImagingPhoto"`.
- Тест навигации файлового менеджера был неустойчив: `event_generate('<Return>')`
  без `when='tail'` не доходил до обработчика, пока X-фокус не передан новому окну,
  и под оконным менеджером разработчика таблица оставалась `['etc']` (6 падений из
  40 прогонов). Под Xvfb в CI событийный фокус отдаётся без WM, поэтому дефект там
  не проявлялся. Теперь навигация в тесте ждёт результат по дедлайну.

### Безопасность

- Валидация IPv4/IPv6 в операции замены IP — закрыта возможность инъекции команды
  через поле адреса (добавлены тесты на инъекции).
- Пароль очищается из памяти сразу после установки соединения.
- Логи с ротацией и правами 0600; секреты маскируются в выводе и в отчётах.
- Профили серверов сохраняются с правами 0600.

### Проверено

- `python -m pytest tests/ -q` — 145 passed.
- Синтаксис совместим с Python 3.7+ (проверено `ast.parse(feature_version=(3, 7))`
  на всех модулях проекта).
- Бинарник Linux x86_64 собран PyInstaller 6.22.3 и запущен: окно создано,
  работает в `mainloop` без ошибок.
